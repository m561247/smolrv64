## The whole run

1 h 41 min wall (6,062.9 s); 1,269,167,272,106 instructions in 998,496,193,487 cycles: **IPC 1.271**,
-1.50% cycles against the synchronous crossing (8f970165, 1.0137 T) for the same work. Per 1000
instructions: 8.83 D$ line fills, 0.70 I$ misses (8.84, 0.71): the same fills, now mostly from the L2.

The back end gives back 14.4 G cycles, most of it outside M: loads that wait on a fill wait 13 cycles
less when the L2 holds the line.

The GB5 SimPoints (the single-core section's 77, the lockstep's drawn DDR model) predicted -2.75%;
the board's single-core wall falls 1.67%, three fifths of it. Clang gains 4.85% against a predicted
9.5%, and Gaussian Blur, Machine Learning and Structure from Motion 37% to 52% of theirs; N-Body,
SQLite and Text Compression match or beat theirs. Why the board's gain is smaller is open; it is not
the DMA snoops the lockstep lacks: booted with the scanout off (no snoop stream; the same bitstream,
https://browser.geekbench.com/v5/cpu/24746971), the run takes 1,000,357,834,135 cycles, +0.19%, and
scores the same (single-core 18, Integer 22; every subtest's rate within 1%).

## Memory

`tools/board/membench/summary.sh` on the same boot, before the run (core cycles, user mode; each
program counts its own):

| a dependent load (`chase2`, one chain) | cycles | 8f970165 |
|---|---|---|
| 16 KiB: a D$ hit (load-use) | 3.0 | 3.0 |
| 256 KiB: beyond the D$, the dTLB's first level holds the page (the L2) | **21.0** | 33.9 (DRAM) |
| 4 MiB: the same and a first-level dTLB miss the second level holds (beyond the L2: DRAM) | 44.6 | 40.5 |
| 64 MiB: a page walk on every load | 71.1 | 73.5 |

| sequential 8-byte accesses (`bw`), bytes a cycle | 32 KiB | 512 KiB | 64 MiB |
|---|---|---|---|
| read | 7.81 | 3.68 | 2.88 |
| write | 7.10 | 5.81 | 5.10 |

An L2 hit is 12.9 cycles shorter than DRAM was; a DRAM access is 4.1 cycles longer, the L2's lookup
and a register each way; a walk is shorter for its page-table entries hitting the L2. Reads at
512 KiB come from the L2 at 3.68 bytes a cycle (from DRAM 3.07); a 64 MiB read stream pays the longer
miss (3.05 -> 2.88).
